Part 0

The setup: learning from examples

In supervised learning we are given examples of inputs together with the right answers, and we want a function that gives the right answer for new inputs. A program that improves at this task by looking at more examples is learning.

\(x^{(i)}\)
input features of example \(i\). Here: sepal length and sepal width of one flower.
\(y^{(i)}\)
the target. Here: 0 for setosa, 1 for versicolor.
\(m\)
number of training examples. Here: 100 flowers.
\(h_\theta(x)\)
the hypothesis: our model's output for input \(x\), controlled by parameters \(\theta\).
\(x_0 = 1\)
a constant feature, so \(\theta_0\) acts as the intercept.

When \(y\) is a continuous number (a price, a temperature) the problem is regression. When \(y\) takes a few discrete values (spam or not, setosa or versicolor) it is classification. Today all three models are linear: they compute \(\theta^T x = \theta_0 + \theta_1 x_1 + \theta_2 x_2\) and differ in what they do with that number.

Ask the roomLook at the scatter plot in the first demo below. Could you draw a straight line that separates the two species? Where would you put it? Learning is the algorithm finding that line by itself.

One practical step before training: we standardize each feature, \(z_j = (x_j - \mu_j)/\sigma_j\), so both features have mean 0 and standard deviation 1. Gradient descent converges much faster when features are on similar scales. The plots still show centimetres.

Part 1 · CS229 notes §1

Linear regression

The simplest model: predict with a weighted sum of the features.

\[ h_\theta(x) = \theta^T x = \sum_{j=0}^{n} \theta_j x_j \]

What is a good \(\theta\)? The cost function

We measure how wrong the model is on the training set with the least-squares cost: square each error, then average. Squaring makes all errors positive and punishes large errors more than small ones.

\[ J(\theta) = \frac{1}{2m} \sum_{i=1}^{m} \left( h_\theta(x^{(i)}) - y^{(i)} \right)^2 \]

Learning now has a precise meaning: find the \(\theta\) that makes \(J(\theta)\) as small as possible.

Gradient descent

Start from any \(\theta\). Compute the slope of \(J\) (the gradient), and take a small step downhill. Repeat. The step size \(\alpha\) is the learning rate.

\[ \theta_j := \theta_j - \alpha \frac{\partial J}{\partial \theta_j} = \theta_j - \alpha \, \frac{1}{m}\sum_{i=1}^{m} \left( h_\theta(x^{(i)}) - y^{(i)} \right) x_j^{(i)} \]

This is the LMS rule (least mean squares). Read it out loud: each example pushes \(\theta\) in proportion to its error. Examples the model already gets right barely move it.

ShortcutFor least squares there is also a closed-form answer, the normal equation \(\theta = (X^TX)^{-1}X^T y\). Gradient descent matters because it still works when no formula exists, which is the case for logistic regression and neural networks. The dashed line in the demo is the normal-equation answer, so you can watch gradient descent arrive at it.

Using regression to classify

Our labels are 0 and 1, so we fit a regression to them and call anything with \(h_\theta(x) \ge 0.5\) a versicolor. The decision boundary is the line where \(\theta^T x = 0.5\).

Try liveSet \(\alpha = 0.01\): it still converges, just slowly. Set \(\alpha = 1.5\): it zig-zags but settles. Set \(\alpha = 1.8\): the cost explodes. Every model has a range of learning rates that works.

Why this is a rough classifier

  • \(h_\theta(x)\) is not bounded: it can say 1.7 or −0.4, which means nothing for a yes/no question.
  • Least squares also penalises points that are correctly classified but far from the line, because they are far from 0 or 1. Far-away points drag the boundary. Result: 99% accuracy, with one setosa (4.5 cm, 2.3 cm) on the wrong side.

We want a model whose output is a probability between 0 and 1. That is logistic regression.

Part 2 · CS229 notes §2.1

Logistic regression

Keep the linear score \(\theta^T x\), but squash it through the sigmoid (logistic) function so the output always lands between 0 and 1.

\[ h_\theta(x) = g(\theta^T x), \qquad g(z) = \frac{1}{1 + e^{-z}} \]
  • \(z \to +\infty\): \(g(z) \to 1\)
  • \(z \to -\infty\): \(g(z) \to 0\)
  • \(z = 0\): \(g(z) = 0.5\), so the boundary is the line \(\theta^T x = 0\)

We read the output as a probability: \(h_\theta(x) = P(y = 1 \mid x; \theta)\).

The cost: likelihood, or cross-entropy

Choose \(\theta\) to make the observed labels as probable as possible (maximum likelihood). Taking minus the log and averaging gives the cross-entropy, or log loss:

\[ J(\theta) = -\frac{1}{m} \sum_{i=1}^{m} \Big[ y^{(i)} \log h_\theta(x^{(i)}) + (1 - y^{(i)}) \log \big(1 - h_\theta(x^{(i)})\big) \Big] \]

A confident wrong answer costs a lot: if the model says \(P(\text{versicolor}) = 0.01\) and the flower is a versicolor, that example costs \(-\log 0.01 \approx 4.6\). A confident right answer costs almost nothing.

The gradient looks familiar

\[ \theta_j := \theta_j - \alpha \, \frac{1}{m} \sum_{i=1}^{m} \left( h_\theta(x^{(i)}) - y^{(i)} \right) x_j^{(i)} \]
Point to stop onThis is the same formula as the LMS rule from Part 1, letter for letter. The only change is what \(h_\theta\) means. The derivative of the sigmoid, \(g'(z) = g(z)(1 - g(z))\), cancels neatly against the log in the cost. Chapter 3 of the notes (generalized linear models) explains why this is no coincidence.
Point outThe background shading is the predicted probability. Watch it sharpen over time. On this pair of species the data can be perfectly separated, so the cost keeps creeping towards 0 and \(\theta\) keeps growing: the model gets ever more confident. The boundary itself stops moving early. Then switch the species to versicolor vs virginica: the classes overlap, the cost levels off, and the shading stays soft. That soft region is honest uncertainty.

Part 3 · CS229 notes §2.2

The perceptron

Frank Rosenblatt's perceptron (1958) was built as a model of a single neuron. It replaces the smooth sigmoid with a hard yes/no threshold.

\[ h_\theta(x) = g(\theta^T x), \qquad g(z) = \begin{cases} 1 & z \ge 0 \\ 0 & z < 0 \end{cases} \]

It learns one example at a time:

\[ \theta := \theta + \alpha \left( y^{(i)} - h_\theta(x^{(i)}) \right) x^{(i)} \]

Read the update case by case. If the prediction is right, \(y - h = 0\) and nothing happens. If a versicolor (\(y=1\)) was called setosa (\(h=0\)), we add \(\alpha x\) to \(\theta\), which raises the score of that flower. If a setosa was called versicolor, we subtract it. Each mistake rotates and shifts the line towards fixing that one point.

Convergence theoremIf some line separates the two classes perfectly, the perceptron is guaranteed to find a separating line after a finite number of mistakes. If no such line exists, it never settles. Try versicolor vs virginica in the demo: the line keeps jumping. Minsky and Papert's 1969 book made this limitation famous (a single perceptron cannot learn XOR), and the fix, many neurons in layers, is where deep learning starts.
NoticeThe perceptron stops at the first line that makes no mistakes. That line can pass very close to some flowers. Logistic regression keeps pushing for confidence on every point. Neither one looks for the line with the widest margin; that is the idea behind support vector machines (CS229 notes, chapter 6).

Wrap-up

What to take home

  • A model is a function with parameters. Learning means choosing the parameters that minimize a cost on the training examples.
  • Gradient descent: compute the slope, step downhill, repeat. The learning rate decides whether you crawl, converge or blow up.
  • Logistic regression is linear regression passed through a sigmoid, trained with a cost that suits probabilities.
  • The perceptron is the hard-threshold version. It is one neuron, and it only works if a straight line can do the job.
